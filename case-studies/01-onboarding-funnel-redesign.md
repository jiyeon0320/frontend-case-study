# Onboarding Funnel Redesign

## Summary

회원가입 후 첫 콘텐츠 탐색으로 이어지지 않고 이탈하는 사용자가 많았습니다.  
PM이 가입 직후 탐색 경험을 강화하는 방향으로 온보딩 개선을 주도했고, 저는 그 방향을 프론트엔드 구조와 사용자 흐름으로 구체화하는 역할을 맡았습니다.

연령·관심사 기반 맞춤 추천 서베이를 포함한 단계형 온보딩 퍼널을 구현하면서, 사용자 상태별 분기, 재진입 흐름, 결과 화면, 이벤트 계측 구조를 설계했습니다.  
그 결과 18일간의 A/B 테스트에서 가입 후 세션 열람률 55.6%, 3일 이내 재방문율 83.9% 개선에 기여했습니다.
<br/>
<br/>
<br/>

## Context

서비스는 어린이 도서 큐레이션 플랫폼이었고, 가입 직후 사용자가 자신에게 맞는 책을 빠르게 탐색하게 만드는 것이 중요했습니다.

하지만 기존 흐름에서는 회원가입 이후 첫 행동으로 자연스럽게 이어지지 않는 구간이 있었고, 가입 직후 화면이 비어 보이면서 사용자가 다음에 무엇을 해야 하는지 바로 이해하기 어려웠습니다.

이 문제는 단순히 화면 하나의 문제가 아니라, **가입 이후 탐색 경험이 제품 구조 안에서 충분히 연결되지 않은 문제**로 보였습니다.
<br/>
<br/>
<br/>

## Team Direction

이 개선은 PM이 주도한 작업이었습니다.

PM은 가입을 단순 완료 절차로 두기보다, 가입 직후 탐색 경험을 강화하는 방향으로 온보딩을 재구성하고자 했고, 연령·관심사 기반의 맞춤 추천 흐름을 핵심 방향으로 제시했습니다.

저는 이 방향을 바탕으로 프론트엔드에서 실제로 동작 가능한 흐름으로 구조화하고, 사용자 상태·분기·재진입·결과 화면·계측까지 포함한 구현을 맡았습니다.
<br/>
<br/>
<br/>

## My Role

프론트엔드 엔지니어로서 맡은 역할은 다음과 같았습니다.

- 단계형 온보딩 플로우 설계 및 구현
- 신규 / 기존 / 미완료 사용자 상태별 분기 로직 설계
- 이탈 이후 재진입 가능한 흐름 구성
- 결과 화면과 후속 탐색 경험 연결
- 온보딩 퍼널 이벤트 계측 구조 반영

즉, 제품 방향 자체를 정한 역할이라기보다,  
**제품 방향을 프론트엔드 구조와 사용자 흐름으로 구현 가능한 형태로 정리하는 역할**에 가까웠습니다.

<br/>
<br/>

## Engineering Focus

이 작업에서 중요했던 프론트엔드 관점의 포인트는 네 가지였습니다.

### 1. 상태별 시작점이 달라야 했다

신규 사용자, 기존 사용자, 온보딩 미완료 사용자는 같은 화면에 진입하더라도 다음 행동이 달라야 했습니다.  
그래서 화면 단위보다 먼저 사용자 상태와 전이 구조를 정리해야 했습니다.

### 2. 중단 후 다시 들어와도 흐름이 이어져야 했다

온보딩 도중 이탈하는 사용자가 있었기 때문에, 처음부터 다시 시작하게 하는 구조보다는 이전 맥락을 이어받는 구조가 필요했습니다.

### 3. 결과 화면이 실제 탐색으로 이어져야 했다

서베이 결과가 단순 완료 화면으로 끝나면 안 됐고, 가입 직후 바로 개인화된 탐색 경험으로 연결되어야 했습니다.

### 4. 개선 여부를 검증할 수 있어야 했다

온보딩은 감각적으로 좋아 보이는 것만으로는 부족했기 때문에, 단계별 이탈과 결과 행동을 추적할 수 있는 계측이 함께 필요했습니다.
<br/>
<br/>

## Implementation

프론트엔드에서는 아래 영역을 중심으로 구현했습니다.

### Step-based onboarding flow

단계형 온보딩 화면을 구현하고, 각 단계가 다음 행동으로 자연스럽게 이어지도록 구성했습니다.

### State transitions and branching

신규·기존·미완료 사용자 상태에 따라 시작점과 후속 행동이 달라지도록 분기 로직을 설계했습니다.

### Re-entry flow

온보딩 도중 이탈하더라도 다시 진입했을 때 흐름이 끊기지 않도록 재진입 구조를 구현했습니다.

### Personalized result screen

연령과 관심사를 기반으로 가입 직후 개인화된 큐레이션을 보여주는 결과 화면을 연결했습니다.

### Event instrumentation

온보딩 단계별 행동과 결과 이후 탐색 행동을 추적할 수 있도록 이벤트 구조를 반영했습니다.

## Result

18일간의 A/B 테스트 결과:

- 가입 후 세션 열람률 **55.6% 개선**
- 3일 이내 재방문율 **83.9% 개선**

이 수치는 특정 UI 요소 하나의 효과라기보다,  
가입 이후 첫 탐색 경험을 더 자연스럽게 연결한 결과라고 봤습니다.

<br/>

## What I Learned

### 1. 제품 방향과 구현 책임은 분리해서 봐야 한다

좋은 협업은 누가 아이디어를 냈는지보다, 그 방향을 실제 서비스 구조로 얼마나 잘 연결하느냐가 중요했습니다.

### 2. 온보딩에서는 화면보다 상태 전이가 먼저다

분기와 재진입이 있는 흐름에서는 화면 설계보다 상태 구조를 먼저 정리해야 구현과 운영이 안정됩니다.

### 3. 계측은 나중이 아니라 처음부터 같이 설계해야 한다

퍼널 개선은 출시 후 감으로 판단할 수 없기 때문에, 실제로 어떤 단계가 좋아졌는지 볼 수 있는 계측 구조가 필수였습니다.
